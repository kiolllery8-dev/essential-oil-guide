## 稽核方法

1. **靜態原始檔掃描**：`html-source/`（111 檔）、`app/`、`public/assets/css/style.css`、`data/oils.json`、`scripts/`。
2. **建置產物驗證**：掃 `out/` 全部 416–420 個 `index.html`，比對 DOM 標題順序、byte offset、內鏈實際輸出。
3. **內鏈圖重建**：以首頁為起點做 BFS，計算每頁的深度、inbound 來源數與 anchor text 分布。
4. **內容深度量測**：剝掉 `<script>`／`<style>` 後計算純文字字元位置，換算每個 h2 區塊的「文件深度百分比」。
5. **修法可行性模擬**：對每條修法先在 script 層模擬（div 平衡、字元數差異、related 陣列輸出、RelatedLinks 分配 before/after），再判定風險。
6. **第二輪覆核**：每條發現獨立重跑證據、主動找反證，凡因果推論站不住、修法會壞事、風險評級失準者一律降級並改寫修法。
