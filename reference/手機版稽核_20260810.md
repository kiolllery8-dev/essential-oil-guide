## S1. Logo 不是連結（模板回歸，全站 416 頁）

- **檔案:行號**：`app/layout.tsx:102`（收尾 `</div>` 在 108）
- **現況**：`<div className="logo-wrap">`。原始模板 `html-source/oil-detail.html:130` 本來是 `<a href="index.html" class="logo-wrap" ...>` —— Next.js 改寫版面時掉了這個連結。建置產物 `out/oil/25/index.html` 只有 `<div class="logo-wrap">`；`public/assets/js/nav.js` 也沒有任何 logo 點擊處理。
- **375px 下會怎樣**：header 是 `position:sticky`，breadcrumb 不是。使用者往下捲之後，畫面上常駐的只剩 logo 與漢堡，此時 logo 不可點 → 回首頁要按漢堡再點「首頁」。另外 `/about/`、`/contact/`、`/disclaimer/`、`/privacy/`、`/404/` 這 5 頁**本來就沒有 breadcrumb**，全程缺一鍵回首頁。
- **怎麼修**：

```diff
- <div className="logo-wrap">
+ <a href="/" className="logo-wrap">
    ...
- </div>
+ </a>
```

  不需要加 `style={{ textDecoration:'none' }}` —— `style.css:48` 已經是 `a { text-decoration: none; }`。樣式完全不用動（`style.css:87` 已有 `.logo-wrap{display:flex}`；`.site-title` / `.site-sub` 各自有明確 color，不會被 `a` 的 green-mid 蓋掉）。附帶好處：`.logo-icon` 是 44×44，變成連結後正好是合規觸控目標。

- **影響頁數**：全站 416 頁（共用 layout）。真正缺一鍵回首頁的是上述 5 頁。
- **覆核判定**：**OVERSTATED**。原報告的「兩次操作」與「全站少一條 sitewide 內鏈」兩個理由都被推翻——410 頁的 breadcrumb 第一顆就是 `<a href="/">首頁</a>` 且手機沒被隱藏；nav 的 `<li><a href="/">首頁</a></li>` 也在每頁 HTML 內（抽屜是用 `translateX(-105%)` 藏，不是 `display:none`，爬蟲照吃）。**降級為「模板回歸修復 + 慣例補強」，優先度排在已知問題一、二之後。**

## S2. 客服聊天泡泡 100% 蓋住「回到頂端」按鈕（351 頁功能完全失效）

- **檔案:行號**：`public/assets/css/style.css:766-781`（觸發點 `app/layout.tsx:178`）
- **現況**：`#backToTop{position:fixed;bottom:32px;right:32px;width:44px;height:44px;z-index:99}`。layout.tsx:178 載入的 `https://chat.intelliverse.tw/widget.js` 內建 `.ivc-btn{position:fixed;right:20px;bottom:20px;width:58px;height:58px;z-index:2147483600}`。幾何：backToTop 佔右緣 32–76px／底緣 32–76px，泡泡佔 20–78px／20–78px → **完全包住**，z-index 差 2,147,483,501。
- **375px 下會怎樣**：實測 `/oil/25/` 與 `/article-sleep/`（375×812）：`document.elementFromPoint()` 打在 backToTop 正中心回傳 `.ivc-btn`；以 41×41 網格取樣，落在按鈕可視圓形內的 1249 點中命中 `#backToTop` 的比例 **0.00%**。使用者每一次按「回到頂端」都被吃掉，改為開啟客服視窗。**這個缺陷與視窗寬度無關，桌機同樣壞著。**
- **怎麼修**：直接改基礎規則（一次覆蓋所有寬度）：

```css
/* style.css:766-781，原為 bottom:32px; right:32px */
#backToTop { bottom: 92px; right: 20px; }
```

  92px 剛好避開泡泡佔用的底緣 20–78px 帶，還留 14px 餘裕。若堅持只動手機，就寫在 `@media (max-width:640px)` 區塊（1580 行起）內，但要另記一筆「桌機仍被遮擋」。

- **影響頁數**：**351 頁**（`out/` 掃描：416 個 index.html 全部載入 widget.js，其中 351 個含 `id="backToTop"` = 302 個 `/oil/*` datasheet + 49 個內容頁）。首頁本來就沒有回頂按鈕。
- **覆核判定**：**CONFIRMED**。逐條驗證通過：style.css 全檔 `#backToTop` 只出現 3 次（766、782 `:hover`、783 `.show`），全都不在任何 media query 內；widget.js 唯一的 media query 是 `@media(max-width:420px)` 且只針對 `.ivc-panel`，不動 `.ivc-btn`；專案內完全沒有 `.ivc*` 覆寫。修法不會壞事——375px 下底部 160px 內其他 `position:fixed` 元素只有畫面外的側邊抽屜與 `pointer-events:none` 的 backdrop。

## S3. datasheet SSR 藥學屬性的 ul/ol 沒有縮排，bullet 掛到版心外（302 頁）

```jsx
<div
  className="od-rich-content"
```

  ⚠️ **一處要誠實修正**：原報告說「外觀不會被改」不正確。inline 的 `fontSize:15 / lineHeight:1.9 / color` 確實贏過 class，但 class 還會帶進 `p{margin:0 0 12px}` 與 `li{margin-bottom:6px}` —— 目前那些 `<p>` 被 reset 清成 margin:0、段落間零間距，加了 class 會**多出段距（是改善，但不是零變化）**。

## R1. `numerology.html` 的 `#partner-sel` 被 inline style 覆寫成 14px，iOS 聚焦會自動放大整頁

- **檔案:行號**：`html-source/numerology.html:684`（JS 產生的人際合盤下拉選單）；對照 `:31` 的 `.num-sel` 定義
- **現況**：
  - `:31` `.num-sel{padding:11px 14px;font-size:16px;font-family:inherit;border:1.5px solid #C8A673;border-radius:10px;...}` ← **本體是對的**（16px 不觸發 iOS 縮放，高約 44px）
  - `:684` `h+='<select id="partner-sel" class="num-sel" style="font-size:14px;padding:8px 12px;">...'` ← inline style 把 16px 打回 **14px**、11px padding 打回 8px。高度 ≈ 14×1.2 + 8×2 + 1.5×2 ≈ **36px**
- **375px 下會怎樣**：`numerology.html` 第 4 行 viewport 是 `width=device-width, initial-scale=1.0`，**沒有 `maximum-scale` / `user-scalable=no`**，代表 iOS 的自動縮放沒有被抑制 → 觸發條件成立。iOS Safari 對 `font-size < 16px` 的表單控制項（含 `<select>`）在 focus 時會**強制 zoom 整個 viewport**，使用者選完對方主命數後畫面停在放大狀態，必須自己雙指縮回去 —— 而這正好是「算完結果、正在往下讀」的關鍵時刻。另外 36px 也低於 44px。
- **怎麼修**：把 inline style 整段拿掉，讓 `.num-sel` 生效：

```js
h += '<select id="partner-sel" class="num-sel">...'
```

  若想保留稍小的視覺，**最低限度也要 16px**：`style="font-size:16px;padding:11px 14px;"`。**iOS 的縮放門檻是 16px，15.9px 就會觸發，不能折衷。**

- **影響頁數**：`/numerology/` 一頁
- **覆核判定**：**CONFIRMED**。四條反駁路徑全部失敗：(1) 引用逐字相符；(2) `numerology.html` 全檔 `@media` = 0 筆，style.css 兩個斷點都只處理 header/抽屜/grid，全檔 `select` 只命中一次是 `user-select:none`，**而且就算真的寫了 `@media{.num-sel{font-size:16px}}` 也贏不了 inline style（必須加 `!important`）**—— 這條反駁在 CSS 層級上根本不可能成立；(3) `out/numerology/index.html`（438KB）grep 到 3 筆 `partner-sel`，inline style 原樣保留；(4) 修法不會撐破版面。

## R2. `numerology.html` 國曆／農曆／民國年／閏月的 label 熱區 25px

- **檔案:行號**：`html-source/numerology.html:137`（國曆）、`138`（農曆）、`139`（`#num-roc` 民國年）、`140`（`#num-leap` 閏月）；父層 `136` 是 `display:flex;flex-wrap:wrap;gap:8px 14px;font-size:14px`
- **現況**：`<label style="cursor:pointer;"><input type="radio" name="cal-type" ...>國曆</label>`，input 沒給 width/height（Chrome 13×13、iOS Safari ≈16×16）。`numerology.html` 全檔 0 個 `@media`；style.css 兩個斷點內容全是 header/nav/grid，**沒有任何 label、input、`#calc` 選擇器**（style.css 甚至完全沒有 input 規則）。`out/numerology/index.html` 第 89-90 行與原始碼逐字相同。
- **375px 下會怎樣**：實測 label 盒 **45×25.19**（國曆／農曆）、**59×25.19**（民國年）。四個角落 `elementFromPoint` 全部命中 label，對文字區（避開 radio）派送 click 後 radio 由 false→true —— **有效熱區是整個 45×25 盒，不是 13×13 的 input**。
  25.19px **已通過** WCAG 2.2 SC 2.5.8 Target Size (Minimum, AA) 的 24×24 門檻，只未達 Apple HIG 44 / Material 48 / WCAG 2.5.5 AAA 的建議值。
  ⚠️ **失效模式被講反了**：radio 點不到是 **no-op**，不會選到錯的值 —— 使用者不可能「不小心選到農曆」，只可能「沒能離開預設的國曆」，而國曆既是 `checked` 預設也是絕大多數情境。真正的風險只剩「少數要用農曆／民國年的使用者點擊未生效」。
- **怎麼修**：在 `numerology.html` 既有 `<style>`（28-41 行）內追加，不動任何 markup：

```css
@media (max-width: 640px) {
  #calc label {
    display: inline-flex; align-items: center; min-height: 44px;
    padding: 0 6px; margin: 0 -6px;
  }
  /* JS 第 378 行會寫 inline style display:inline-block，優先權高於樣式表，需針對性蓋掉；
     用屬性選擇器，確保第 377 行寫 display:none 時不會被 !important 強制顯示 */
  #calc #leap-wrap[style*="inline-block"] { display: inline-flex !important; }
  #calc input[type=radio], #calc input[type=checkbox] {
    width: 20px; height: 20px; accent-color: #7A5A8E;
    margin-right: 8px !important; vertical-align: middle !important;
  }
}
```

  `margin:0 -6px` 抵銷 padding，讓 136 行 flex 的 14px column-gap 視覺不變，但熱區左右各多 6px。
  實測三狀態皆正確（375×812）：預設國曆 `#leap-wrap` display=none、寬 0，該排高 44；切農曆 display=flex、盒 68×44，文字垂直位置與兄弟完全一致（misalign 0px），單行、`scrollWidth 375 = innerWidth 375` 無溢出；切回國曆 display 回到 none、寬 0，隱藏邏輯未被破壞。
  註：`blend.html` 也有自己的 `#calc`，但此規則寫在 numerology 的頁內 `<style>`，不會外溢。

- **影響頁數**：`/numerology/` 一頁
- **覆核判定**：**OVERSTATED**（機制、數字、後果三項都錯或誇大）。
  ⚠️ **機制錯**：label 不是 inline。136 行父層是 `display:flex`，137-140 的 label 是 flex item，依 CSS Display 規範被 blockify，實測 `computedDisplay = "block"`。「label 沒有 display 宣告 → 維持 inline」整段推理不成立。
  ⚠️ **數字錯且方向相反**：實測 25.19px 正好 = `font-size 14px × line-height 1.8` —— 高度**正是被 line-height 撐開的**，與「不會被父層 line-height 撐開 ≈ 18px」完全相反，18px 低估實際熱區約 40%。
  ⚠️ 原修法未預見 `#leap-wrap` 的 inline style 衝突（JS 第 378 行寫 `display:inline-block` 優先權高於樣式表），會導致「閏月」文字比同排兄弟高 9.4px。上面的修法已補上。
  **由於僅為未達建議值（非違反 AA）且是高流量頁，建議降為低優先度，不急著動。**
